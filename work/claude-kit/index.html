ClaudeKit

Two scores for every request: one for how it was asked, one for what came back.

ClaudeKit is our kit for working with Claude Code. A mentor grades each request before the work runs. A critic grades the result afterwards. A scorecard puts both numbers on one board, so the person asking is measured alongside the model answering.

Starting point

Two people shape the work. Only one of them was being measured.

When someone works with an AI model, the result comes from two places: the request they write, and what the model does with it. The model's half has always been easy to review, because you can read the change it made. The request that started it scrolls past and is rarely written down.

So any measure of the work was really a measure of the model alone. When a round went wrong, there was no way to tell whether the ask or the answer was the weak part.

What we found

The gap between the two scores is the useful number.

The mentor grades the request before any work runs, before anyone knows how it will turn out. The critic grades what came back against what was asked. Read together, the two scores show where a round went wrong. A clear request that still missed points to the model. A vague request that landed anyway was luck, and luck isn't a process. When both are low, the mentor's note says why. When both are high, the process worked.

Each side has its own measures. A request is scored on its framing, its leverage and what it carried forward. A delivery is scored on whether the asked-for thing happened, the evidence behind it, and whether it stayed in scope.

Where we went

A mentor, a critic, and a scorecard.

The mentor works before anything runs. It suggests how the request could be framed more clearly, then grades it. The critic is a new agent every time. It has no memory of how the work was made, only the request and the result, so it can see what the builder could not. The scorecard turns both sets of grades into XP, levels, streaks and badges on a single board.

Grades stay in the project where they were earned, in a record that is only ever added to. Everything on the board is worked out from that record each time it is shown, so a streak that ended two days ago reads zero. A section called “What this could not see” lists what is missing, such as a side left ungraded or turns where no grade followed. The kit asks the person using it what to call them, once, instead of guessing.

What's next

Smaller now, and clear about what it hasn't proved yet.

In September 2026 we rebuilt the kit and took out what it had outgrown: two officer roles, a crew of six agents, and a safeguard built for Pastry Pirates' unattended build. What remains is one plugin with three parts. The kit reviews its own work too. Its critic graded the rebuild partial, 72 out of 100, and was right.

The next step is the one everything else rests on. Nobody has yet installed the plugin and watched it run through a full live session, so that comes first.
